## Реализованная история 2

- Вступление в том числе в закрытую гильдию по действующему приглашению.
- Ввод кода с главной страницы либо открытие ссылки; превью до подтверждения.
- После входа или регистрации сохраняется переход к приглашению.
- Проверяются авторизация, формат кода, существование и срок, включая точную границу истечения.
- Новое членство имеет роль member и 0 XP. Существующие роль и XP сохраняются.
- Повторное вступление через тот же или другой код не дублирует членство: get_or_create опирается на unique_guild_member, обработка выполняется в транзакции.
- После вступления доступны гильдия и её привычки; право создавать привычки остаётся у владельца.
- Ошибки видимы, кнопка блокируется во время запроса; успех содержит переход в гильдию.

## Найденные прежние ограничения

- «Сегодня» использует часовой пояс пользователя, а отметка выполнения — дату сервера. На границе суток возможна разница.
- На главной уровень 7 и 1840/2000 XP заданы константами. Прогресс гильдии также частично использует демонстрационные значения. Лидерборд использует реальные данные; личный профиль остаётся историей 4.
- При сетевой ошибке/5xx создание гильдии переключается на локальное демо.
- JWT refresh endpoint есть, но автоматическое обновление access-токена в apiRequest отсутствует.

Эти ограничения не изменялись в рамках историй вступления и лидерборда.

## Реализованная история 3 (10 SP)

- GET /api/guilds/<guild_id>/leaderboard/?sort=xp|streak доступен только участникам; без входа — 401, вне гильдии — 404, неверная сортировка — 400.
- XP берётся из GuildMember.xp этой гильдии, без пересчёта наград по изменённой сложности привычек.
- Стрик: последовательные календарные даты с хотя бы одним выполнением привычки этой гильдии. Серия заканчивается сегодня или вчера по часовому поясу каждого участника; невалидный пояс заменяется UTC. Дубликаты дат и будущие даты не увеличивают серию, пропуск прерывает её. Это принятое правило реализации: документ спринта не уточняет формулу стрика.
- Сортировка по выбранному показателю по убыванию, затем по второму показателю, затем по user_id по возрастанию. Места последовательные, даже при равенстве показателей.
- Данные получаются тремя запросами независимо от количества участников. Расчёт стрика использует сохранённые completed_on; прежнее ограничение даты сервера при записи выполнения сохраняется.
- Экран /guilds/<id>/leaderboard открывается со страницы гильдии, показывает место текущего пользователя, все XP и стрики, состояния загрузки/ошибки и повтор запроса. Выбор сортировки сохраняется в URL и после входа/регистрации.
- Новые миграции не нужны; сквозной браузерный сценарий не проверялся.
