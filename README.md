# inHabit

Геймифицированный трекер привычек с гильдиями.

## Стек
Django + DRF + PostgreSQL, React, Docker Compose.

## Запуск

### Frontend

```bash
cd frontend
pnpm install
pnpm dev
```

Приложение будет доступно по адресу `http://localhost:5173`. В режиме
разработки запросы к `/api` Vite перенаправляет на backend-контейнер.

Для production-сборки frontend:

```bash
docker compose up --build frontend
```

## Спринт 1: текущее состояние

Реализованы подготовка и истории 1–3 и история 6:

- Создание гильдии с владельцем и просмотр только своих гильдий.
- Создание привычки владельцем: название, ежедневное расписание или выбранные дни недели.
- Сложность и вес награды: лёгкая — 10 XP, средняя — 20 XP, сложная — 30 XP; награда = базовые XP × вес (1–10).
- Форма добавления привычки и список привычек на странице гильдии. Демо доступно по `/guilds/demo`, данные демо сохраняются в текущей сессии браузера.
- Регистрация, вход и выход по JWT. Защищённые страницы перенаправляют гостя на вход; запросы к API выполняются только с `Bearer` access-токеном.

Следующие задачи спринта: история 4 — список на сегодня с учётом часового пояса; история 5 — идемпотентная отметка выполнения и начисление XP. Сейчас XP в карточке привычки показывает будущую награду; фактическое начисление ещё не реализовано.

### Регистрация и вход

Откройте `/register`, чтобы создать учётную запись, либо `/login`, чтобы войти. После успешного действия приложение сохраняет access- и refresh-токены в `localStorage`; вручную добавлять токен через DevTools больше не нужно. Access-токен действует 15 минут, refresh-токен — 7 дней. При выходе refresh-токен отзывается сервером, а данные сессии удаляются из браузера.

API аутентификации:

- `POST /api/auth/register/` — `{ "username", "email", "password", "timezone" }`;
- `POST /api/auth/login/` — `{ "username", "password" }`;
- `POST /api/auth/refresh/` — обновление access-токена;
- `GET /api/auth/me/` — текущий пользователь;
- `POST /api/auth/logout/` — `{ "refresh" }`, отзыв refresh-токена.

### API привычек

Все запросы требуют заголовок `Authorization: Bearer <access_token>`.

- `GET /api/habit-difficulties/` — справочник сложности и базовых XP.
- `GET /api/guilds/<guild_id>/habits/` — список для участников гильдии.
- `POST /api/guilds/<guild_id>/habits/` — создание только владельцем.

Пример тела создания:

```json
{
  "name": "Утренняя зарядка",
  "schedule": "weekdays",
  "weekdays": [1, 3, 5],
  "difficulty": "medium",
  "xp_weight": 2
}
```

Дни недели используют ISO-нумерацию: понедельник — 1, воскресенье — 7. Для `daily` список дней нормализуется в `[]`. Поле `xp_reward` рассчитывает сервер (в примере — 40 XP); клиент не задаёт награду напрямую. Название ограничено 120 символами. Ответ гильдии содержит `is_owner` для отображения доступных действий.

### Проверка изменений

Серверные проверки используют отдельную SQLite-базу в памяти без PostgreSQL и без подключения к рабочей базе:

```bash
cd backend
python manage.py test --settings=config.settings_test
python manage.py makemigrations --check --dry-run --settings=config.settings_test
```

После обновления примените миграции к рабочей базе:

```bash
docker compose exec backend python manage.py migrate
```

PostgreSQL намеренно не публикует порт на хост: к нему обращается только backend-контейнер. Не добавляйте реальный `.env` с паролями в Git; используйте `.env.example` как шаблон.

Проверки frontend:

```bash
cd frontend
pnpm test
pnpm build
```
