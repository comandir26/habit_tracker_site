# Спринт 2, история 4: профиль и прогресс (9 SP)

Реализовано 29.10.2026 поверх актуальной origin/develop (`9bb8ac3`).
Источник требований: [Спринт №2 — Matiz](https://docs.google.com/document/d/1D8x3DN2rrXzU51mcNEYw9eGZiyWEuoP5EMqOa3wGat8/edit).

## Поведение

- Защищённая страница `/profile` доступна по ссылке «Мой профиль» в панели пользователя.
- Никнейм, суммарный XP, уровень, текущий стрик и полоса прогресса приходят с сервера.
- На главной карточка пользователя также показывает реальный прогресс вместо уровня 7 и фиксированного XP. Гостю личный прогресс не показывается.
- Есть состояния загрузки, ошибки и кнопка повторного запроса. При открытии страницы данные запрашиваются заново.

## API и правила

`GET /api/auth/profile/` требует Bearer-токен; без авторизации — 401. Возвращает только профиль текущего пользователя, независимо от параметров запроса.

Пример ответа:

```json
{
  "id": 1,
  "username": "alex",
  "total_xp": 245,
  "level": 3,
  "xp_in_level": 45,
  "xp_per_level": 100,
  "xp_to_next_level": 55,
  "streak": 4
}
```

Документ спринта не задаёт формулу уровня. Принято правило: уровень 1 при 0 XP; каждый следующий уровень требует 100 XP; `level = total_xp // 100 + 1`. На точной границе нового уровня полоса начинается с нуля.

XP — сумма сохранённых `GuildMember.xp` текущего пользователя во всех его гильдиях. Изменение награды привычки не пересчитывает уже заработанный XP. Стрик объединяет выполнения привычек всех текущих гильдий пользователя; несколько выполнений в один день дают один активный день. Чужие выполнения и гильдии без членства не учитываются. Серия заканчивается сегодня или вчера по часовому поясу пользователя; пропуск прерывает серию, будущие даты игнорируются, невалидный пояс заменяется UTC. Используется общая функция расчёта стрика с лидербордом.

Схема базы не меняется. Существующее ограничение записи выполнения по дате сервера сохраняется; профиль использует сохранённые `completed_on`.

## Проверка

- 59 серверных тестов, включая 8 новых: границы уровня, пустой профиль, авторизация, сумма XP, объединение стрика, пропуски, чужие данные и часовые пояса.
- 27 клиентских тестов, включая 3 новых: контракт API профиля, ошибки и некорректные данные.
- Production-сборка frontend успешна; новых миграций нет.
- Серверные проверки выполнены на отдельной SQLite-базе в памяти. Сквозная проверка в браузере и PostgreSQL не выполнялась.

В рамках этой ветки реализована только история 4 «Профиль и прогресс».
